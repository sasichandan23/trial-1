@@ the whole idea @@

Same model. Same diff.

Both of these came out of one run against a live memory bank. The only variable is whether the reviewer could recall what this team had already decided.

── memory off
The loop calls _provider_status(refund) for each refund, which makes a network request per item. Consider batching the status requests. Correct. Forgettable. Any tool says this.
── memory on
This is the exact shape of the bug that caused the 41-minute checkout outage. You must batch these requests or parallelize them to avoid exhausting the connection pool. precedent: one call per item inside a loop exhausted the Postgres pool. It matched an N+1 database query to a per-item API call. Nobody told it those were the same bug.

3 what changes

The agent is told to call recall_team_memory before it writes code, so it follows your conventions the first time instead of being corrected afterwards. It can also store a rule when you state one, record an incident, and run a full review.

Nothing is hosted. The client launches the server as a local process and talks over pipes. The only remote piece is the memory bank.

@@ how it works @@

The model is stateless. The bank is not.

The review itself is unremarkable. What matters happens either side of the model call.

  1. recallBefore reviewing, query the bank for what this team has decided that bears on this change. Budgeted to about 1,000 tokens, so prompt size does not grow as the bank does.
  2. reviewThose memories enter the prompt under headings the model is told to treat as binding rules, not as background reading.
  3. retainAfterwards, and again once a human responds, write back what happened. The bank grows with every pull request.

four kinds of memory

kindwhat it iswhy it earns its place
feedbackHow a reviewer answered a specific finding, and why A rejection encodes a judgment you cannot read off the codebase. The most valuable thing here.
conventionA team rule, also stored as a Hindsight directive Rules must apply to every review. Similarity search is the wrong retrieval for a standing rule.
incidentA bug or outage tied to a code pattern A post-mortem stops being a page nobody reads and starts flagging the next pull request.
reviewA summary of each review posted It knows what it already said.

where memory changes the outcome

RETENTION

Knowledge survives people

The engineer who knew why you don't do X leaves. The rejection they recorded stays and keeps shaping reviews.

PREVENTION

Post-mortems do something

An incident becomes a rule that flags the next change repeating the pattern, instead of a document nobody opens again.

ONBOARDING

House style from day one

A new joiner's first reviews already carry the team's conventions, learned from everyone who came before them.

SIGNAL

It gets quieter, not louder

Teams switch review bots off when noise beats signal. This one narrows over time as it learns what you turned down.

@@ notes from building it @@

Including the one we nearly published

— WRONG

Our A/B test compared two models

Memory-off ran on one provider; memory-on fell back to another after a rate limit. The result looked great and proved nothing. Both halves are now pinned to one provider, and the run warns if they ever differ.

+ LEARNED

Rejections beat acceptances

An accepted suggestion only tells you the reviewer was already right.

+ LEARNED

Rules and facts retrieve differently

A convention should apply whether or not the diff looks familiar. Moving rules into directives fixed a whole class of inconsistency.

+ LEARNED

Say how to match, not just what

One paragraph telling the model to match incidents on the shape of a bug rather than its wording changed behaviour more than any extra context.

— WRONG

A slow test is a bug report

The suite jumped to 68 seconds. A rate-limit test was busy-waiting a full minute, because sleep was mocked inside a loop that needed the clock to move.

+ LEARNED

Wait on purpose

Pacing against a rolling token budget is cheaper than retry backoff, and deterministic, which matters when anything downstream depends on timing.
